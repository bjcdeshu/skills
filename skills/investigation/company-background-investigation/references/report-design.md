# HTML 报告与神经网络式关系图

目录：阅读顺序；根类型文案；八个入口；八个问题；十一类档案；主体与案例；关系图 2.0；视觉与交互；打印；复用模板。

## 一、阅读顺序

首页先解释调查根节点——公司、人物、投资方、机构、产品或品牌——再沿相关的人、组织、资本和产品深入。每条主线交代连接事实与理解根节点的作用。新材料回填对应判断、主体和案例，维持完整叙事。

以五分钟理解为首页目标：清楚说出调查对象做什么或是谁、由谁持有和经营（或控制、参与哪些组织）、业务与资金怎样流动、本次选择最受哪些事实影响。把重点证据的日期与适用范围放在附近；主张细节、长履历、完整股东链和原始附件通过展开或档案入口阅读。首屏保留核心判断和明显的继续阅读入口。

默认三层阅读：

1. 快速认识：根节点身份、关键人物或组织、经营方式和最重要发现。
2. 理解关系：人物及关联组织主线、股权穿透、共现伙伴、实际案例、业务/资金流程与核心问题。
3. 查阅档案：全部主体、历史事实、原始来源、实图、时间线及可复用资料。

用户实际提供或指定已有成稿时，保留其可用结构与认可的入口。首次调查使用下列默认组织，按根类型、行业和法域调整栏目措辞。示例中的主体、问题或风格不带入新任务。

## 二、默认八个阅读入口

| 入口 | 应直接回答的内容 | 适合呈现 |
| --- | --- | --- |
| 01 先认识公司 | 实际业务、法律主体、关键判断与证据 | 导语、事实卡、真实官网或业务图像 |
| 02 股东与人员沿革 | 权益、经营负责人、治理与人员变化 | 股东表、人物卡、时间线 |
| 03 关联公司主线 | 通过谁或什么连接到哪些主体 | 关系网络、逐支说明、主体档案 |
| 04 业务与资金 | 客户、交付、获客/采购、收费、成本和收益分配 | 业务流、资金流、精确金额对照 |
| 05 重点案例 | 产品或项目、目标公司角色、成果与维护 | 实图案例卡、版本/交付时间线 |
| 06 团队与发展 | 人数口径、岗位五维、雇佣主体、发展与资质 | 关键工作解释、团队/岗位记录、发展时间线 |
| 07 核心问题 | 本次最关心问题的回答及证据 | 可展开问答、相关主体链接 |
| 08 完整资料档案 | 深入查阅全部事实、来源和历史 | 分类档案、搜索、来源索引与导出 |

首页数字标明日期与范围，直接从资料计算。标题和问题可适应任务，核心覆盖保持完整。

其他根类型保留八入口结构，按调查主线改写。人物根的默认入口：

| 入口 | 应直接回答的内容 |
| --- | --- |
| 01 先认识人物 | 身份锚点、当前主要职务、核心判断与证据 |
| 02 任职与持股 | 存续与已注销、吊销组织中的全部身份与期间 |
| 03 关联网络 | 人物—组织—人物的关系图与路径 |
| 04 股权穿透 | 直接与间接持股、持股平台与穿透比例 |
| 05 共现伙伴 | 二跳伙伴频次、角色组合与任期重叠 |
| 06 隐性关联与同名排查 | 信号边、关联交易线索与同名候选 |
| 07 核心问题 | 本次最关心问题的回答及证据 |
| 08 完整资料档案 | 人物、组织、证据留存与时间线 |

投资方根以“出资结构—投资组合—共同出资方—退出与回报”展开，产品与品牌根以“权利主体—开发与运营—发行渠道—市场表现”展开，机构根以“职能与隶属—负责人—合作与资金—公开记录”展开。随附 `example-person-data.json` 展示人物根的完整入口配置。

有可比经营数据时，用 `metrics` 呈现少量关键数字，正文用 `block.chart` 比较同口径期间或组成，用 `block.table` 展示精确对照。主张按钮按需展开事实类型、时间、定位和实际留存状态；完整来源索引保留原始 URL。字段见 [data-model.md](data-model.md)。

## 三、默认八个核心问题

将问题改写为适合目标公司的自然表达；更新真实旧报告时保留已有问题身份。

1. 谁持有和经营公司，治理及人员如何变化？
2. 公司实际向谁提供什么，交付能力体现在哪里？
3. 哪些关联主体最有助于理解公司，各通过什么事实连接？
4. 重点产品或项目体现了哪些可核验的工作与成果？
5. 项目、生产或增长费用由谁承担，收入怎样回到公司？
6. 公司经过怎样的发展形成当前业务？
7. 团队人数、岗位、工作地点和雇佣主体分别是什么口径？
8. 哪些公开差异、争议或经营事实最影响当前判断？

每题给当前回答、具体支持事实、相关人物/公司/产品入口及经营含义。证据按问题需要组织，实际缺口在该题集中说明一次。

入职或岗位调查把第七题具体化为实际工作、运行流程、所需经验、行业知识和工作条件，并将最影响选择的答案带回首页。保留八问结构。

人物根的默认八问：

1. 该人物实际控制或深度参与哪些组织，控制链怎样形成？
2. 谁是他长期、反复合作的伙伴，各以什么角色出现？
3. 过往组织为什么结束，对当前判断有什么含义？
4. 有哪些可核验的工作成果、作品或产品？
5. 其控制的组织之间有哪些交易、资金或关联方关系？
6. 职业轨迹经过怎样的发展形成当前角色？
7. 是否存在同名、别名或身份混淆，如何排除？
8. 哪些公开记录、争议或尚未公开的事实最影响当前判断？

## 四、默认十一类资料档案

1. 主要法域的登记主体、股东与治理。
2. 其他法域主体与运营、发行或销售迁移。
3. 全部关键人物、履历与任职。
4. 完整产品、项目与案例图集。
5. 股权与其他具体关系分图。
6. 资本金额、财务与各期业务指标。
7. 网站实图、域名和适用的站点登记/备案。
8. 招聘、雇佣主体与团队。
9. 公开差异、客诉、司法行政记录及其他争议。
10. 完整发展时间线。
11. 全部原始材料、主张依据与证据留存清单。

按调查实际合并空栏目或调整名称；人物根可将第 1、2 类合并为“组织档案（存续与已注销、吊销）”，并把第 5 类改为“股权穿透与共现伙伴”。保留真实旧稿仍有效的历史资料。档案引用统一主体、来源与图片记录，使正文、图谱和详情同步。

## 五、人物、组织与案例

### 人物档案

依次呈现与根节点的连接路径、当前/历史角色、关键工作、履历、权益和任职、相关组织及产品、共现伙伴、身份依据和出处。履历使用有证据的时间线；“合伙人”“负责人”等称呼注明具体职责和材料时间。用户指定人物可由全站搜索、图谱和人物目录直接找到。同音异人搜索结果分别列出可辨认的职业信息，候选身份显示四锚点结论。

### 组织档案

依次呈现连接路径、法律全称/法域/登记号、登记状态（存续、注销、吊销）与经营状态、股东和管理、穿透比例、对应业务、产品/客户/供应商、关键事件与来源。将共同股东、任职、采购、开发、运营和发行关系准确命名。必要时保留原文法律术语及简明解释。

### 产品与项目案例

以真实图片、精确角色和完整解释组织重点案例，其他案例放入可检索图集：

- 产品、型号、稳定 ID 或项目名称，以及市场/平台和有效时间。
- 解决的问题、客户需要及目标公司承担的具体工作。
- 创作者、权利主体、开发者、制造者、运营者、发行/经销方和客户。
- 原始公布成果及后续观察，附指标定义、日期、分母和说话主体。
- 收费、采购、订阅、售后、客服、更新及维护记录。
- 关键事件、问题反馈、回应和已知结果。
- 原始材料及实际页面、产品或附件图像。

按行业绘制“获客或采购—交付—结算—维护”流程。资金流独立标出谁付款、谁收款、计费依据和期间。用户从案例可以继续打开相关人物或组织。

## 六、神经网络式关系图 2.0

### 含义与数据

以调查根节点为中心的可探索关系网，按人物、公司、品牌、产品、投资方和机构分型。六类主体使用不同形状——公司圆角方形、人物圆形、产品菱形、品牌空心菱形、投资方六边形、机构圆角三角形——并配合类型色，灰度打印仍可辨认；根节点加强调外环并放大。节点距离、面积和颜色只表达图例定义的信息，控制与权益依具体关系事实呈现。

关系按族区分：资本（持股、出资、合伙份额）实线，治理与任职、业务关系虚线，信号边点线，候选与争议使用醒目的状态样式，历史关系降低不透明度并标注时间。每条边带指向目标的箭头，双向事实分别显示。资本边始终显示比例或金额标签，其他标签随缩放、悬停或选中出现。边详情逐条展示同一主体对的不同事实、日期与来源。

### 视图与布局

- 核心网络：默认显示最有解释价值的主体，并保留通向根节点的中间节点。
- 全部主体：提供完整探索，次要名称适当收起，搜索或点选后聚焦。
- 所选周边：显示所选主体的直接关系及其回到根节点的路径。

三种布局可切换并带过渡动画：

- **径向**：按距根节点的层级成环，资本方、治理人物、业务伙伴、产品与候选主体各占稳定扇区。
- **层级（股权穿透）**：上游股东在上、下游被投企业与产品在下，治理人物与业务伙伴分列两侧，使用正交折线减少交叉。核心边以资本为主时默认采用此布局。
- **力导向**：用于全部主体的密集探索。

### 必要交互

- 姓名/全称/别名/产品搜索；视图、布局切换；缩放（点击画布后滚轮缩放，或 Ctrl+滚轮与双指缩放）、适配画布、拖动、全屏、返回根节点。
- 类型与关系族筛选标签（资本、任职/治理、业务、信号/关联、待核/争议）及历史关系开关；隐藏主体时显示提示并可一键清除。
- **A↔B 路径查找**：任选两个主体，列出最多五条最短路径，逐步显示关系、方向、日期与来源，并在图上高亮。默认只走确认边，可选纳入历史关系。
- **共现伙伴表**：显示 `__computed.co_occurrence` 的伙伴、分数、存续与已注销/吊销共同组织数、角色组合和共现期间；伙伴两人及以上时出现。
- 选中节点后显示摘要卡（类型、穿透比例、主要关系、打开完整档案）；列表视图提供与图谱等价的结构化目录；全屏时显示缩略导航图。
- 信息不只依靠悬停显示；搜索结果标明主体类型和身份信息，避免同名混淆。

导航路径可以双向查找，展示时恢复原始箭头，例如 `公司甲 ← 股东乙 → 公司丙`。每一步附关系、有效日期和出处。默认确认路径遵循可确认的关系；候选、信号和争议状态单独显示，历史路径注明时间。权益或控制分析采用相应资本和治理材料，穿透比例来自 `__computed.ownership`。

### 可读性与可访问性

根节点突出，次级节点按明确类型和重要性区分。长名称在图上缩短，在详情显示全称。布局稳定，控制标签密度、交叉、遮挡和点击区域。全图过密时保持可读核心图与聚焦能力。

提供图谱对应的列表或档案入口，便于键盘和小屏阅读。手机保留搜索、展开与主体详情；点选后立即出现可读内容。侧栏和对话框有标题、关闭操作和清晰焦点，关闭后回到触发处。

## 七、视觉与页面表现

有实际旧稿时延续其适用设计；首次制作默认采用“墨与印”编辑主题：暖白纸面、墨色正文、印章红强调色，并提供深色模式与手动切换（偏好保存在本地，打印始终使用浅色）。颜色集中由设计令牌定义，正文与界面文字对比度达到 WCAG AA。证据等级以符号加文字标示：● 公开事实、◐ 公司披露、○ 用户提供、◇ 综合分析，待核、争议与历史状态另有样式。

采用系统字体（中文优先苹方、冬青黑体、微软雅黑 UI、思源黑体），正文 16px、行高 1.8、行宽不超过约 40 个汉字，数字使用等宽数字。桌面左侧目录持续定位并显示阅读进度，小屏折叠为顶部栏。首页分三层：标题与计数、核心判断引文与身份卡、关键指标条与编号发现列表。

- **侧栏档案**：主体、关系对、主张与来源在右侧非模态侧栏打开，正文保持可见；支持返回历史、标签页（概览、关系、履历与事实、图片、来源）与可复制的深链接，Esc 关闭。小屏改为底部弹层。
- **来源悬停卡**：悬停或聚焦来源标签时显示标题、发布者、日期、定位与摘录，点击在侧栏打开，不跳离当前阅读位置。来源标签带种类简字（登、官、店、媒、司、用、析、档）。
- **图片灯箱**：点击证据图片或身份卡缩略图放大查看，支持缩放、拖动、左右切换与图注来源。
- 表格表头固定、数值右对齐；全站搜索覆盖正文、主体、别名、产品和来源，结果可直接打开内容。无实际内容的栏目自然省略。

将 CSS、JavaScript、数据和主要图像嵌入一个 HTML，保留原始来源链接。离线可阅读正文和主要交互。

页面仅呈现调查事实、必要解释和操作词。资料合并、实现架构、调试与验证过程留在内部记录。外部原文作为转义后的文本或已核验图像进入报告。

主张及存档细节收在依据侧栏和来源档案，首页维持阅读节奏。日期缺失按一次实际未知表达；哈希与文件路径用于深入核对，正文优先解释其支持的事实。

## 八、打印

按 A4 版式输出：首页为标题、核心判断、身份卡、指标与发现；关系图单独成页，打印前自动适配画布并显示全部标签、比例与箭头，附带形状与线型图例；随后输出“关系明细表”（起点、关系、终点、比例/金额、日期/期间、状态、来源，按资本、治理、业务、待核排序）与按证据等级分组的主张附录。打印隐藏侧栏、灯箱、悬停卡与操作控件，展开核心正文、完整档案和详情资料，内部来源标签打印为编号，外部地址打印完整 URL，避免长卡片截断。

## 九、复用模板

随附 `assets/report.html`、`assets/report.css`、`assets/report.js` 提供结构、样式与交互；`scripts/build_report.py` 可将调查 JSON 和实际取得的图片构建为单文件。解析当前技能目录后使用这些相对资源，按运行时和报告需要调整。

模板用于首次制作或合适的改版；真实旧报告优先保留可用结构。演示数据（公司根 `example-data.json`、人物根 `example-person-data.json`）只用于了解字段及试运行，正式调查以本次取得的事实替换。构建后实际打开文件，验收来源入口、搜索、图谱、路径查找、共现表、深浅色、移动端与打印。
